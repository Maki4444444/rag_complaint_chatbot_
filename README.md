# RAG Complaint Chatbot: CrediTrust Financial

An internal RAG-powered chatbot that lets CrediTrust's Product, Support,
and Compliance teams ask plain-English questions about customer
complaints and get evidence-backed answers, with retrieved source
complaints shown alongside every response instead of manually digging
through thousands of unstructured complaint narratives a month.

## The business problem

CrediTrust Financial serves 500,000+ users across East Africa and
receives thousands of complaints a month with no efficient way to spot
trends in the unstructured text. This project delivers a working
internal chatbot so non-technical staff can ask questions like "why are
people unhappy with Credit Cards?" and get answers grounded in actual
retrieved complaints, not a black-box summary.

## Success metrics

- **Evaluation coverage** a fixed, representative question set across
  all 4 product categories, each scored for retrieval relevance and
  answer faithfulness, not just spot-checked.
- **Answer faithfulness** generated answers stay grounded in retrieved
  sources (no unsupported claims) in at least 85% of evaluated responses.
- **Runtime resilience** the app degrades gracefully (clear
  user-facing message, no crash) under at least 3 defined failure modes
  (LLM API timeout/error, empty retrieval results, malformed/empty
  input).
- **Response latency** chat interface returns a full streamed answer
  in under 5 seconds per query under normal conditions.

## Setup

```bash
git clone <this-repo-url>
cd rag-complaint-chatbot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Create a `.env` file in the repo root:
```
HF_TOKEN=hf_your_token_here
```
A **Read**-scope token from `https://huggingface.co/settings/tokens` is
sufficient — this authenticates embedding-model downloads (higher HF Hub
rate limit, faster downloads) and, later, the Task 3 generation/judge
LLM calls. The app and scripts work without it, just slower and with a
lower request ceiling.

## Task 1 EDA & Preprocessing

```bash
jupyter notebook notebooks/01_eda_preprocessing.ipynb
```

Loads the full CFPB complaint dataset (~9.6M rows), analyzes product
distribution and narrative length/coverage, filters to the 4 target
product categories (Credit Card, Personal Loan, Savings Account, Money
Transfer) with a non-empty narrative (→ 480,564 complaints), and cleans
each narrative through a 3-stage pipeline: boilerplate-opener stripping,
noise removal, and NLP normalization. Saves
`data/processed/filtered_complaints.csv`.

```bash
pytest tests/test_preprocessing.py -v
```

## Task 2 Chunking, Embedding, Indexing

```bash
python -m src.build_sample_index
```

This is the actual Task 2 deliverable script. Draws a 12,500-complaint
stratified sample (proportional to each category's real share, per
`docs/PROGRESS_LOG.md`), chunks narratives with `RecursiveCharacterTextSplitter`
(chunk_size=500, chunk_overlap=50 matches the Tasks 3–4 pre-built
store spec), embeds with `sentence-transformers/all-MiniLM-L6-v2`, and
persists a ChromaDB collection to `vector_store_sample/`, with a
`build_manifest.json` recording exactly which complaint IDs were
sampled.

```bash
pytest tests/test_chunking.py tests/test_embedding.py tests/test_sampling.py tests/test_build_sample_index.py -v
```

For the sampling-strategy visualization and chunk-size experimentation
referenced in the report:
```bash
jupyter notebook notebooks/02_chunking_embedding_indexing.ipynb
```

`vector_store_sample/` has been built end-to-end against the real
480,564-row `data/processed/filtered_complaints.csv`, with real network
access and real embedding computation — it's a genuine, populated
ChromaDB collection, not built from test fixtures. Exact sample
composition (which complaint IDs, per-category counts, chunk totals) is
recorded in `vector_store_sample/build_manifest.json`.
